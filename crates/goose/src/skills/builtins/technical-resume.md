# Fresher resume for campus placements

## The format recruiters expect

One page. No photo, no age, no marital status, no declaration line. Plain
single-column layout, because two-column and graphical templates are mangled
by applicant tracking systems. Save and send as PDF, named with the
student's own name.

Order for a fresher: contact details, education, technical skills, projects,
internships, achievements, positions of responsibility.

Projects come before internships only when the projects are stronger, which
for most students they are.

## Contact line

Name, phone, professional email address, GitHub, LinkedIn. An email like
`coolguy123@` costs interviews. Use the college address or firstname.lastname.

## Education

Degree, branch, college, year of graduation, and CGPA. Include the CGPA if
it is above roughly 7, and include class ten and twelve percentages, which
Indian recruiters do screen on. Do not hide a backlog that a transcript will
reveal.

## Writing a project bullet

The weak version names the technology. The strong version names the
outcome. Use this shape:

    Built <what> using <technology> that <measurable outcome>

Every bullet starts with a past-tense action verb and contains a number
wherever one honestly exists: users, records, percentage improvement,
dataset size, response time, accuracy. "Improved page load from 4.2s to
1.1s" is worth more than "worked on performance optimisation".

Three bullets per project is enough. Include the GitHub link.

## Technical skills

Group them: languages, frameworks, tools, databases. List only what survives
questioning. Anything on the resume is fair game in the interview, and a
claimed skill the student cannot discuss does more damage than an omitted
one. Drop "MS Office" and self-assessed proficiency bars.

## Before the interview

For every project on the page, be able to answer: why that approach, what
was the hardest bug, what would you do differently, and which part did you
personally write. Interviewers probe for ownership in team projects.

## How to help

When reviewing, quote the student's own bullet, say what is weak, and give
the rewrite. Do not invent achievements or numbers they have not stated:
ask for the real figure. Keep the whole thing to one page and say what to
cut when it overflows.
